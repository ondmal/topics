# Topics

Ideas from my experience in software architecture and team leadership, each
described in some depth. A topic is not a project report: it describes an
approach and why, not what is wired today. The projects on
[ondmal.github.io](https://ondmal.github.io) are the evidence a topic may point
to.

| Topic | One line | Page |
|---|---|---|
| Documentation as a source artefact | How to document software components in the age of AI: documentation next to the code, written during the change with an AI agent doing the mechanical part, reviewed in the pull request, published on merge — and what is worth writing at all. | [ondmal.github.io/topics/documentation-as-code](https://ondmal.github.io/topics/documentation-as-code/) |

## Files

- One folder per topic: `<topic>/index.md` is the page, `<topic>/images/` its
  hand-authored SVG diagrams.
- [`_config.yml`](_config.yml) — GitHub Pages site settings.
